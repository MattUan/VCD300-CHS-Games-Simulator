# 原盘加载参数与兼容接口

## 可复核依据

镜像为2352字节原始扇区，ISO9660用户数据位于每扇区24字节后。目录提供300个NEWROM/Gxxx.BIN，各自占用不同起始扇区。SHA256去重为150款。转换脚本直接读取镜像，不依赖旧提取文件。

BIN中的大端MIPS代码使用虚拟基址 **0x4001A400**。每个游戏存在连续四个12字节函数，形如 `lui v0,hi; jr ra; addiu v0,v0,lo`；前三个返回同一地址，第四个返回数据结束地址。函数指令中的低16位必须按有符号数解释。减去基址后得到BIN内的真实载荷起止位置；不扫描NES指令或猜测固定偏移。

150款全部找到唯一函数组。载荷长度分布：97款0xA000，5款0xC000，24款0x10000，24款0x20000。

| 载荷长度 | 程序 | 图形 | 生成映射器 |
|---|---:|---:|---:|
| 0xA000 | 32KB | 8KB | 0 |
| 0xC000 | 32KB | 16KB | 3 |
| 0x10000 | 32KB | 32KB | 3 |
| 0x20000 | 128KB | CHR RAM | 2 |

程序初始化会两次调用第三个地址函数。32KB类设置上半区读基址为程序起点减0x8000；128KB类设置固定上半区基址为程序起点加0x10000，从程序最后一个16KB bank读取复位向量。转换器验证对应MIPS指令，拒绝不匹配布局。48/64KB类的图形换页代码从程序起点+0x8000开始选择8KB bank；128KB类构造函数分配图形RAM。

构造函数写入 `gp+0x1C7` 的常量决定镜像方式：0清除PPU地址A11，为纵向镜像，iNES位0=1；1清除A10，为横向镜像，iNES位0=0。转换器对构造函数进行常量跟踪，记录写入指令位置，拒绝不能确定的值。载荷字节原样复制，不继承旧版的逐字节补丁。

所有300项的BIN起点、大小、SHA256、载荷范围、程序映射证据位置、镜像写入位置、向量与ROM SHA256均保存在tests/disc-layout.json/csv。

## 原盘特殊指令

解释器初始化代码中的分发表位于BIN偏移0x35B4；末7款使用相同含义的旧表0x35AC。转换器验证两种表的九个处理函数入口。

| 原盘指令 | 标准CPU含义 |
|---|---|
| EF | BMI / 30 |
| F2、FB | BNE / D0 |
| F3 | BCC / 90 |
| F4、FA、FC | BEQ / F0 |
| F7、FF | JMP绝对 / 4C |

原盘处理函数在分支/跳转之外还做调度等待；NES核心已有自己的CPU/PPU时序。本版在x6502.cpp的实际指令读取后、周期表查询前转换CPU指令含义，保留操作数和图形字节。这同时覆盖从RAM执行的代码、间接跳转后的代码及程序换页，避免静态扫描误改数据。

CNROM类的原盘写端口为$6802，值低位选择8KB图形bank。headless.cpp在Mapper 3游戏加载后安装相应写接口，先同步PPU再setchr8；不执行普通卡带的总线冲突掩码。标准地址的映射器功能仍由FCEUX负责。

`vcd_diagnostics`导出两个uint32：执行的原盘特殊指令次数、$6802写入次数。原有9字段统计结构和加载/运行/画面/音频接口保持兼容。

此核心专门用于本盘转换产物，不能作为通用NES核心来保证非官方6502指令兼容性。本版没有提供存档状态功能；新增端口的独立bank缓存尚未加入通用即时存档序列化。

## V0.70 beta：G122与同步等待

G122/G272在$FFE0存在AD 02 20 29 40 F0 F9 60注入等待，轮询$2002的bit6。真实NES核心在无背景重叠、或sprite隐藏时不会产生原盘解释器的无条件阶段信号，因而可以显示标题但停止持续读取输入。原盘MIPS代码在BIN的0x8330无条件写gp+0x24=0x40，0x83B4清除该值。

本版仅对同时符合Masahiro程序签名和注入等待签名的Mapper 3程序安装$2002读包装。在CPU执行该等待、显示行113–239期间提供兼容bit6，不修改其他程序或其他读取位置。该信号用于恢复原盘程序流程，行时序为近似，未做实机逐行对照。G122已通过10000帧输入/画面验证。

Mapper 3的标准$8000–$FFFF端口也改为直接图形换页，以匹配原盘无卡带总线冲突行为。vcd_diagnostics第二字段现在统计两种端口的图形换页总次数。
